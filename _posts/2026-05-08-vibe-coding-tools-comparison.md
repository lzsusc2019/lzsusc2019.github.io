> **快速回想**： 
> - **纵向脉络**：算力和上下文窗口的突破，将 AI 编程从 Copilot 的“单行补全”推向了 Claude Artifacts 的“网页直出”与 Agent 的“多文件接管”。
> - **横向格局**：Claude (Artifacts/Code) 是普及度最广的官方底座；Cursor 是前端独立开发的印钞机；Gemini CLI 守住了极客高度定制化的底线；OpenCode 是数据敏感大厂的高墙；Copilot 退守庞大遗留系统的打字机。
> - **交汇判断**：模型智商已非壁垒，真正的护城河是对本地项目工程上下文（Engineering Context）的深度挂载能力。
{: .prompt-info }

直到 2023 年底，程序员的焦虑还停留在“Copilot 补全的代码有没有 Bug”。但到了今天，社区里讨论的已经是 Vibe Coding——不需要懂具体的语法，只要描述清楚你的需求和“感觉”，AI 就能把系统搭出来。

这种从“代码补全器”到“赛博包工头”的转变，并不是某家大厂突然开窍，而是被上下文窗口（Context Window）的算力暴力推着走的。

回看 2021 年 GitHub Copilot 刚出来的时候，它只能缩在 VS Code 的侧边栏里。当时的 AI 模型一次只能吃下 4K 的上下文，大概也就是几个代码文件的长度。它没法知道你隔壁文件夹的路由配置，只能靠着你当前敲下的几行字母，笨拙地猜测下一行。在那个年代，“局部补全”是唯一诚实的商业模式。

转折点发生在 2023 到 2024 年。当大模型可以吞下 128K 甚至 200K 的代码时，事情变了。Anthropic 推出了 Claude 3.5 Sonnet 和惊艳的 Artifacts 功能，第一次让开发者在网页上就能实时预览写出的前端组件；紧接着，Anysphere 团队做出了一个极为野蛮且冒险的决定：直接 Fork 整个 VS Code，做出了 Cursor。Cursor 宁肯背负极高的用户迁移成本，也要直接拿到底层的文件系统权限，把整个代码库变成可以随时检索的知识库。与此同时，Anthropic 官方下场推出了 Claude Code，开源社区也端出了 OpenHands，把 AI 塞进了独立的终端和沙箱里，让它们自己去跑测试、改 Bug。

至此，Vibe Coding 的基础设施搭建完毕。但当我们把目光收回到当下，真正在一线干活的开发者们，真的都靠 Vibe 活下去了吗？其实并没有。不同的工程复杂度，硬生生把这些工具逼进了截然不同的生态位。

### Claude (Artifacts & Claude Code)：全球普及的“原汤化原食”
如果我们讨论全球活跃度最广的工具，绝对绕不开 Claude 本身。无论是网页端的 Artifacts，还是官方的终端工具 Claude Code，它都占据了极其核心的生态位。

- **真实体验**：Artifacts 彻底降低了 Vibe Coding 的门槛。连非技术人员都可以用大白话在浏览器里直接生成并运行一个 React 贪吃蛇游戏，甚至还能分享链接给别人玩。而最近推出的 Claude Code 则是 Anthropic 亲自下场做的 CLI 工具，主打“原汤化原食”——由于是官方出品，它对 Claude 模型的特性挖掘到了极致，在终端里解析项目目录和执行系统命令时非常丝滑。
- **隐形槽点**：网页端的 Artifacts 始终像个玩具沙箱，一旦你想把它生成的代码合并到自己庞杂的本地工程里，就会面临痛苦的手动拼接。而 Claude Code 虽然官方正统，但在一些特定的私有化工作流定制上，显得过于封闭。它活成了全球受众最广的“大一统底座”，但在某些极致垂直场景下，依然需要其他工具来补位。

### Cursor：独立开发者的“致富机器”与前端利器
拿目前风头最盛的 Cursor 来说，它虽然底层严重依赖 Claude 3.5 的智商，但在工程体验上却走出了自己的路。

- **真实体验**：如果你想用周末时间手搓一个记账网页，你只需要在 Composer 面板里打字描述需求，它能瞬间帮你把 React 组件、CSS 样式甚至假数据全都安排明白，所见即所得的体验让人极度上瘾。
- **隐形槽点**：成也全栈，败也全栈。一旦进入后端高度抽象的微服务架构中，由于缺乏对业务链路的深层理解，它经常会像个莽撞的实习生，把原本正常的接口改得面目全非。它活成了 0 到 1 的冲刺王者，却很难做精细的局部手术。

### Gemini CLI：终端原教旨主义者的自留地
当很多人在争论哪个 GUI 编辑器更好用时，有一批后端老炮和 SRE 工程师根本不想离开黑乎乎的 Terminal。这就是 Gemini CLI 这类工具的生态位。

- **真实体验**：开发者直接让 CLI 去读取线上的 Nginx 报错日志，或者丢给它一个需求，让它批量生成发版脚本。与官方的 Claude Code 不同，Gemini CLI 的杀手锏在于“极度的可定制性”。它可以挂载你本地私有的 Markdown 规约（比如本项目严格的排版规则），让 AI 彻底沦为遵循你意志的执行机器。
- **隐形槽点**：纯文本的交互让习惯了点击鼠标的人无从下手。它是一把锋利但挑人的瑞士军刀，精准命中了那些需要底层系统穿透力和深度定制流的极客。

### OpenCode：厂网高墙内的“妥协与倔强”
无论是 Claude Code 还是 Cursor，都需要把代码传到外网，这在金融或军工企业是绝对的红线。于是 OpenCode 这类基于沙箱和本地模型的开源方案成了唯一的选择。

- **真实体验**：虽然大家都在吐槽本地部署的 Llama 或 DeepSeek 在零样本生成上有些“人工智障”，部署维护起来更是耗时耗力，但“数据不出内网”这一条，就足够让它稳坐钓鱼台。它也许笨重，但它活成了企业内网里那座足够安全的围墙。

### GitHub Copilot：巨头温床上的“超级打字机”
至于曾经的先驱 GitHub Copilot，它似乎错过了这场 Vibe Coding 的狂欢。

- **真实体验**：它很难根据一句高层指令去重构十几个文件。但如果你身处一个有着上百万行历史包袱的遗留系统中，每天的任务只是修修补补、写写测试，Copilot 那种毫无存在感、随叫随到的低延迟内联补全，依然是打工人最好的麻醉剂。

## 三、交汇与终局：Vibe 的尽头依然是 Engineering

把这些工具的发展史和如今的生存现状叠在一起来看，Vibe Coding 的泡沫其实正在消退。

各家大模型在“写出一段无 bug 算法”上的能力已经无限趋同。未来的竞争不再是谁的模型更聪明（连 Cursor 最引以为傲的底层也是 Claude），而是**谁能更深地扎进你的工程环境里**。它不仅要读懂代码，还要懂你们团队隐秘的命名规范，懂你历史依赖的某个框架版本坑，懂为什么要用特定的分布式锁。

Vibe Coding 许诺了一个“只要有 idea 就能做软件”的美好幻觉。但在幻觉之下，托底的依然是坚硬的 Engineering。AI 可以帮你极速敲打键盘，但架构的边界、沙箱的安全、以及最后那次决定生死的 Code Review，依然牢牢攥在人类工程师的手里。
